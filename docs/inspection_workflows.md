## 1. End-to-End Investigation User Journey

Phase 4 completes the full operational workflow for revenue protection analysts and field supervisors:

```
[ Inspection Queue ]
       │
       ▼  (Select Meter / Click Row)
[ Inspection Details Drawer ]
       │
       ├─────────────────────────────────────────┐
       ▼ (View Full Work Order)                   ▼ (Analyze in Workbench)
[ Forensic Inspection Ticket ] ──────────► [ Meter Analysis Workbench ]
       │                                          │
       ├───────────────┐                          ▼
       ▼               ▼                   (Review SHAP, Signatures,
[ Export Ticket ] [ Export Queue ]         Temporal Windows, Financial ENV)
   (JSON format)    (RFC 4180 CSV)
```

1. **Inspection Queue (`/#queue`):** Operator monitors high-risk meters sorted by Expected Net Value ($ENV > 0$).
2. **Drawer Quick-Look:** Clicking any queue row slides out the Inspection Details Drawer with immediate telemetry metrics and financial rationale.
3. **Forensic Inspection Ticket (`InspectionTicketView`):** Clicking "View Full Work Order" opens the official field dispatch work order document.
4. **Meter Analysis Workbench (`/#meter`):** Clicking "Analyze in Workbench" carries the exact meter ID and evaluation date into the interactive time-series and diagnostic panels.
5. **Data Export:** Instant, validated download of work orders as structured JSON or the queue as RFC 4180 compliant CSV.

## 2. Forensic Inspection Ticket Document (`InspectionTicketView`)

The work order is structured according to utility compliance standards:

### 2.1 Header & Metadata Block
- **Ticket Identifier:** Monospace format `TCK-{YYYY-MM-DD}-{HASH8}` (e.g., `TCK-2016-10-30-EF550F26`).
- **Evaluation Period:** Authoritative evaluation cutoff date.
- **Meter Identifier:** Full 32-character hexadecimal meter ID.
- **Distribution Feeder:** Distribution substation/feeder ID (e.g., `FEEDER-SUB-04`).
- **Customer Classification:** Residential or Commercial.

### 2.2 Operational Recommendation Banner
- Prominent dispatch status badge: `Physical Inspection Recommended` ($ENV > 0$) or `Monitoring Only (No Dispatch)`.
- Priority queue rank (e.g., `Queue Rank: #1`).
- Active policy rule (`Dynamic Expected Net Value (ENV)`).

### 2.3 Financial & Economic Justification
Four-card economic breakdown:
- **Calibrated Tamper Probability:** $p_i$ (e.g., $99.31\%$).
- **Estimated Recoverable Leakage:** Total kWh volume (e.g., $17,986.50\text{ kWh}$).
- **Net Economic Value (ENV):** Projected net gain after dispatch cost ($p_i R_i - C_{\text{dispatch}}$).
- **Crew Dispatch Cost:** Fixed operational expense ($₹100.00$).

### 2.4 Evidence & Signature Sections
- **Model Evidence & Top Drivers:** Primary SHAP contributors formatted in log-odds margin space.
- **Electrical Tampering Signatures:** Rule-based flags (Sustained step-downs, behavioral shifts) with magnitude and duration.
- **Temporal Pattern Intervals:** Explicit calendar windows highlighting the deviation period.
- **Counter-Evidence & Mitigating Factors:** Objectively noted seasonal or baseline mitigations.

### 2.5 Regulatory & Field Caveat
Every inspection ticket ends with the required regulatory disclaimer:
> *"CONFIDENTIAL FIELD WORK ORDER: This inspection recommendation is generated by algorithmic revenue protection models based on consumption telemetry anomalies. Field technicians must conduct physical verification of meter integrity, seal status, and wiring prior to initiating formal regulatory recovery proceedings."*

## 3. Data Export Specifications (`exportUtils.ts`)

Export functions adhere to enterprise security and RFC standards:

### 3.1 Individual Ticket Export (JSON)
- **Function:** `exportTicketAsJson(ticket: InspectionTicketResponse)`
- **Format:** Formatted JSON (`application/json;charset=utf-8`, 2-space indentation).
- **Filename Convention:** `inspection_ticket_{meter_id}_{evaluation_period}.json` (e.g., `inspection_ticket_620E9685_2016-10-30.json`).
- **Data Integrity:** Fully preserves nested explanation structures, temporal evidence windows, signature lists, and financial floats. No frontend rounding or truncation.

### 3.2 Inspection Queue Export (CSV)
- **Function:** `exportQueueAsCsv(tickets: InspectionTicketResponse[])`
- **Format:** RFC 4180 compliant CSV (`text/csv;charset=utf-8`).
- **Filename Convention:** `inspection_queue_{YYYY-MM-DD}.csv`.
- **Field Escaping:** Safe handling of commas, quotes (`"..."`), carriage returns, and newlines in text fields (such as narrative summaries and signatures).
- **Exported Columns:**
  `rank, ticket_id, meter_id, evaluation_period, customer_type, feeder_id, tamper_probability, calibrated_probability, estimated_leakage_kwh, estimated_recoverable_revenue, dispatch_cost, env, decision_rule, inspection_recommended, signatures`

## 4. State Management & Navigation Continuity

- **Selected Meter Context:** State preserves meter ID, evaluation period, and model version across all view transitions.
- **Browser History Integration:** Hash-based routing (`#queue`, `#meter`, `#insights`, `#overview`) supports browser back/forward buttons without losing state.
- **Honest Degraded Handling:** Network timeouts or offline statuses trigger clear warning banners while retaining currently loaded ticket data for offline review.
